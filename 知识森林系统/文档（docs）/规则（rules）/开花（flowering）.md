# 开花规则：问题驱动的多领域开花

## 触发方式
**仅由问题触发。**
1. 用 `问题模板（t-question）` 创建问题笔记。
2. 通过外部 Work Buddy 发送指令：“基于当前问题，在知识森林中开花”。

## 核心逻辑：一个问题即开花，各领域各开各的花
同一个问题丢进森林，**不是只有一棵树来回答，而是所有相关的树都会开花**：
- AI 先做**关联性分析**，识别与问题相关的领域；
- 每个相关领域**基于自己的养分和视角**独立开花——读书 开出理论视角的花、新媒体 开出运营视角的花、产品设计 开出产品视角的花……同一问题，不同领域开出的花**各不相同**；
- 各领域的花按领域存放，互不混淆，但都回链到同一个问题笔记。

## Work Buddy 多花生成流程
1. **问题理解**：读取问题笔记全文。
2. **关联性分析**：扫描所有领域种子，识别与问题相关的领域（按养分相关度排序；无相关领域的可不开花）。
3. **逐领域根系检索**：对每个相关领域，检索该领域的养分：
   - 该领域的概念叶、底层逻辑、枝条、历史果实、已有花朵
   - 土壤碎片（包括未链接的，按需检索）
   - **全森林共享的 堆肥（Compost）养分**（施肥后所有根系都能吸收，开花时按需激活）
4. **开花前检索报告（默认关闭，可激活）**  
   - 若激活，Work Buddy 先输出“找到的养分清单”，由你确认或补充后再生成方案。  
   - 当前版本默认跳过，直接进入方案生成。
5. **逐领域知识碰撞与方案生成**：
   - 对每个相关领域，AI 将该领域检索到的知识片段进行组合、类比、嫁接，生成**该领域视角的候选解法**（1~N 个）。
   - 单领域方案数量由 AI 根据问题复杂度和养分多样性动态决定，通常 2-5 个。若仅有一个靠谱方案，允许生成1个；若养分丰富，最多不超过7个。
   - 每个方案除核心理念外，必须标注：
     - **所属领域**（这朵花是哪棵树开的）
     - **创新程度**（低/中/高）
     - **风险等级**（低/中/高）
     - **所需资源**（时间、精力、外部依赖）
6. **写入花笔记**：为每个方案创建 `花-问题标题-编号` 笔记（frontmatter 标注 `question` 与所属领域），包含上述信息和执行步骤草案、成功标准、风险假设；**花笔记按领域存放于对应领域的 `花朵（Flowers）/` 子目录**（花朵属于各自这棵树，不混入森林根目录），并在问题笔记回链所有花朵。

## 人工筛选与测试
- 审查所有花朵，根据创新程度、风险、资源选择一朵或多朵实践。
- 可要求 Work Buddy 生成“沙盒测试”方案，低成本验证关键假设。
- 实践过程记录在花笔记的 `## 实践日志`。

## 与嫁接的关系
- 若方案中需要跨领域知识，Work Buddy 会自动创建嫁接笔记，并将嫁接枝作为养分来源。
- 你也可以在问题笔记中主动要求嫁接，如“用游戏化的即时反馈解决员工培训参与度”。
