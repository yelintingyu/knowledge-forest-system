# 开花规则：问题驱动的多方案生成

## 触发方式
**仅由问题触发。**
1. 用 `问题模板（t-question）` 创建问题笔记。
2. 通过外部 Work Buddy 发送指令：“基于当前问题，在知识森林中开花”。

## Work Buddy 多花生成流程
1. **问题理解**：读取问题笔记全文。
2. **根系检索**：扫描 Obsidian Vault，找到与问题相关的：
   - 土壤碎片（包括未链接的，按需检索）
   - 领域种子
   - 几何主干概念及枝叶
   - 历史果实（尤其是避坑警示和可复用模式）
3. **开花前检索报告（默认关闭，可激活）**  
   - 若激活，Work Buddy 先输出“找到的养分清单”，由你确认或补充后再生成方案。  
   - 当前版本默认跳过，直接进入方案生成。
4. **知识碰撞与方案生成**：
   - AI 将检索到的知识片段进行组合、类比、嫁接，生成**多个候选解法**。
   - 方案数量由 AI 根据问题复杂度和养分多样性动态决定，通常 2-5 个。若仅有一个靠谱方案，允许生成1个；若养分丰富，最多不超过7个。
   - 每个方案除核心理念外，必须标注：
     - **创新程度**（低/中/高）
     - **风险等级**（低/中/高）
     - **所需资源**（时间、精力、外部依赖）
5. **写入花笔记**：为每个方案创建 `花-问题标题-编号` 笔记，包含上述信息和执行步骤草案、成功标准、风险假设。

## 人工筛选与测试
- 审查所有花朵，根据创新程度、风险、资源选择一朵或多朵实践。
- 可要求 Work Buddy 生成“沙盒测试”方案，低成本验证关键假设。
- 实践过程记录在花笔记的 `## 实践日志`。

## 与嫁接的关系
- 若方案中需要跨领域知识，Work Buddy 会自动创建嫁接笔记，并将嫁接枝作为养分来源。
- 你也可以在问题笔记中主动要求嫁接，如“用游戏化的即时反馈解决员工培训参与度”。
