# 根系规则：从土壤吸收养分

## 根的本质
根是**连接网络**。它把土壤中的碎片（原始信息）与种子、树干节点关联起来，实现“选择性吸收”。  
每个原始碎片就像腐烂的叶子、果实或昆虫，**身上携带多种元素（标签）**，可以被多棵树的根系吸收。同一碎片可以同时滋养多棵树。

## 生根方式

### 方式一：手动生根（初次引入 + 全局扫描）
- **首次手动/AI生根**：当你放入一个新文件到土壤（soil），你或 Work Buddy 分析其内容，给它打上**标签**（标签即元素，如 `#用户体验`、`#转化率`、`#认知偏差`）。同时，手动或通过 AI 建议，将该文件链接到相关种子和/或主干概念。这一步建立初始根系。
- **自动建链（已存在多棵树时）**：当放入第二个文件，AI 不仅会为第二个文件与当前的树建链，还会**自动扫描已有大树**，检查第二个文件是否包含已有树需要的养分（即是否有相同的标签或语义匹配）。若有，自动建立双链。这样根系会随着新文件的加入而自动延伸。
- **长出新生枝叶的提示**：当新文件携带了某个已有树尚未覆盖的标签/概念，系统会提示“该碎片含有树『XX』的新养分，是否在主干上长出新枝叶？”

### 方式二：按需生根（开花时动态检索）
- 当你提出一个问题触发开花时，Work Buddy 会在全 Vault 中**临时检索**与问题相关的碎片，即使这些碎片之前未被任何树链接。
- 检索到的碎片若对生成方案有价值，会被临时用作养分；同时，开花结束后，AI 会建议你是否将这些碎片**永久链接**到相关树上（“将这次开花发现的养分固定为根系”）。

### 文献的营养化：拆解为概念叶片（长成枝条）
- 当一份文献（书、文章、报告等）被确认与某领域相关后，AI 将其**拆解为多个核心概念**（一文献多概念）。
- 文献笔记作为**枝条**从树干长出（`枝条模板（t-branch）`，`type: branch`，见枝叶规则）。
- 每个核心概念 → 生成**一片概念叶片**（挂在枝条上），一概念一叶。
- 文献原件保留在 `土壤（soil）` 中作为来源；枝条是相关叶片的**营养入口**。
- 拆解的同时，提炼可沉淀的**底层逻辑** → 追加到树干（见主干构建规则）。
- 同一文献的概念可同时滋养多棵树（跨领域概念分别链入各自大树）。

## 根的健康：链接数即吸收强度
- 一个土壤碎片被链接的次数越多，说明它被多棵树吸收，养分浓度越高。
- 在碎片笔记的 Frontmatter 中可用 `links-count` 字段记录（由 Dataview 自动统计），或直接通过双链数量判断。

## 根系修剪：仅针对长期无链接的碎片
- **原始文件原则上是只读、只增、不删**，以保持土壤的原始性。
- 但当土壤碎片积累极多（例如 > 500 条），且某些碎片**连续 180 天** `links-count: 0`，可启动清理评估：
  - AI 分析该碎片对既有树和未来可能开花的潜在影响。
  - 若判断为“低潜力”，则提示你**手动清除**（移至 `堆肥（Compost）` 并保留副本）。
- 极少链接但未达阈值的碎片，由 AI 定期分析其对开花结果的影响，给出“保留/清除”建议，你审核后操作。

## 根网可视化
- 利用 Dataview 查询每个碎片的 `file.inlinks` 和 `file.outlinks`，可绘制出“菌根网络”——哪些碎片同时滋养了多棵树。
