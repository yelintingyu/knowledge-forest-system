# 系统架构：问题驱动的森林生态

## 整体流程
1. **蓄土**：所有碎片信息直接丢入 土壤（soil），无需整理。
2. **播种**：用 `种子模板（t-core-seed）` 定义你关注的领域（如“新媒体”），允许同时多颗、允许休眠；**立干即自动生成领域五结构**（树干/枝条/叶片/花朵/果实）。
3. **生根**：手动或 AI 辅助将 土壤（soil） 碎片链接到种子和主干。新文件加入时 AI 自动扫描已有大树，匹配建链。
4. **长干**：投入营养文献，AI 分析相关性建链，提炼底层逻辑形成树干；核心文献可用几何主干解构后并入。
5. **展叶**：日常笔记链回主干概念。
6. **开花**：提问 → AI 做**关联性分析**，识别相关领域 → 每个相关领域**逐领域检索全林养分**（含未链接碎片与**全森林共享的堆肥**）→ 各自生成 2-5 个领域视角的解法（含创新度、风险、资源标签）→ **产出按领域存入各领域的 花朵（Flowers）/ 子目录**，并回链问题笔记。
7. **结果**：大果实践后 AI 生成 4 个判定标准并建议评级，小果人为判好/坏；**果实存入该领域 果实（Fruits）/ 子目录**。
8. **反哺**：果实分解为土壤新养分，修正领域认知或生成避坑警示。
9. **修剪**：处理黄叶、剪枝；黄叶落叶进入**全森林共享的 堆肥（Compost）**（施肥后所有根系吸收）；极长期无链接的碎片经人工确认后移除。

## 技术实现
- **Obsidian** 知识库本体，双链和 Frontmatter 驱动。
- **Dataview** 动态查询营养值、黄叶、可开花枝条。
- **Work Buddy** 外部 AI 应用，通过文件读写或 Local REST API 交互，所有操作记录日志。
