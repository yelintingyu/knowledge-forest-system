# 标准指令（Standard Commands）

> 本文件是使用者与 AI（Work Buddy）协作的**标准指令集**。每条指令按知识森林系统 v2.5 规则执行。
> **使用方法**：复制对应指令发给 AI，AI 即按规则执行；执行完成后 AI 必须同步更新 `log.md`。

---

## 一、基础操作

### 1. 扫描土壤并建链
- **场景**：土壤（soil）新增了文件/碎片后
- **指令**：
```
扫描 土壤（soil） 中的新碎片/文件，分析内容，识别其与已有领域种子（如 读书、新媒体）的相关性；
注意多对多关系：一份文献含多种营养，可交错供给多个领域；相关的建立链接（原始文件 ↔ 枝条），
相关概念拆解为概念叶挂到对应枝条，底层逻辑提炼入树干；跨领域可供给的标注「可滋养：[[领域]]」；
最后更新 log.md。
```
- **预期**：新碎片进入根系网络，无孤立文件
- **注意**：遵守「土壤只增不删」；未经确认不得删除任何文件

### 2. 文献接入（一文献多叶）
- **场景**：土壤新增一本书/论文/报告（PDF、EPUB 等）
- **指令**：
```
分析 土壤（soil） 中的《书名》，按「一文献多叶」规则接入读书领域：
1. 建枝条：创建 枝条（branches）/书名-读书笔记.md（type: branch，含原始文件双链）；
2. 拆概念叶：提取 3~6 个核心概念，每个建一片概念叶（叶片（leaves）/，含概念定义/我的理解/来源营养/延伸链接）；
3. 提炼底层逻辑追加到树干（编号管理）；
4. **识别交叉营养**：若文献还含有其他领域的营养，标注「可滋养：[[其他领域]]」；
5. 更新种子根链接与年轮日志、log.md。
```
- **预期**：一份文献 → 1 根枝条 + 3~6 片概念叶，全部链接闭合
- **注意**：
  - 概念叶必须挂在对应枝条（parent-node），不直接挂树干
  - **默认单条处理（一素材一枝条）**：每份文献/素材独立成一根枝条，不合并；同一系列的素材也逐份建枝，除非明确提示"合并"

### 3. 盘点领域状态
- **场景**：想了解某领域（大树）当前状况
- **指令**：
```
盘点 读书 领域的当前状态：底层逻辑几条、枝条几根、概念叶几片、双链多少、有无黄叶/孤立碎片，
用表格输出，并指出养分最集中的概念（供开花参考）。
```

## 二、生长操作

### 4. 立干 / 长枝条（含机制二：全土壤扫描）
- **场景**：新建领域种子后，或需要为领域补充底层逻辑
- **指令**：
```
为领域种子「XX」立干：用 树干模板（t-trunk） 创建 树干-XX.md（领域基石 + 底层逻辑清单）。
立干后执行「机制二」：扫描全部已有土壤文献，把相关文献建链到新领域——
生成该领域视角的底层逻辑、抽枝生叶（建枝条+拆概念叶）；
注意结合该领域优化，不照搬其他领域的枝条/概念（同一文献在不同领域提炼的营养不同）。
后续每份文献的营养，把提炼的底层逻辑持续追加（编号管理）。
```
- **预期**：新领域一立干就吸收全土壤的相关营养；树干成为该领域所有枝条/叶片的吸附中心

### 5. 展叶（新增概念）
- **场景**：日常学到新概念、案例、数据
- **指令**：
```
把「概念名」作为概念叶加入 叶片（leaves）/（叶片模板 t-leaf）：
概念定义、我的理解、来源营养（文献/碎片）、延伸链接；
parent-node 指向所属枝条（如 读书笔记），并与相关概念叶互链。
```

### 6. 开花（问题驱动）
- **场景**：遇到需要解决的实际问题
- **指令**：
```
针对问题「问题描述」进行开花：
检索 读书 领域全部养分（概念叶、底层逻辑、枝条、历史果实，含未链接的土壤碎片），
生成 2~5 个可行方案，每个方案标注：核心依据（引用的概念/逻辑）、创新度、风险、所需资源。
```
- **预期**：多方案供选择，每个方案可追溯知识来源

### 7. 结果与复盘
- **场景**：方案实践后
- **指令**：
```
对「方案/项目」进行结果复盘：
1. 评定果实：大果（AI 生成 4 个判定标准）/ 小果（直接答案）；
2. 好果 → 提炼可复用模式写回树干；坏果 → 分析原因，教训回土壤；
3. 更新 果实（Fruits） 与 log.md。
```

### 8. 嫁接（跨领域）
- **场景**：想让两个领域的概念杂交
- **指令**：
```
把「A领域的概念/枝条」嫁接到「B领域」：分析二者的连接点、杂交后的新可能，
输出嫁接方案（含可行性评估），并在 B 领域建立链接（标注嫁接来源）。
```

## 三、维护操作

### 9. 修剪与黄叶处理
- **场景**：发现黄叶（90 天未被引用）或需要清理
- **指令**：
```
检查 叶片（leaves） 中的黄叶（连续 90 天未被引用、链接数 ≤1）：
可激活（变绿）或落叶——打 #fallen-leaf，移至 堆肥（Compost），提取摘要后存放，可删除原文件；
堆肥可纳入土壤，开花时适时激活（施肥）。
```

### 10. 归档（枯枝）
- **场景**：剪除整根枝条（结构化知识不再使用）
- **指令**：
```
把「枝条名」整根剪除：标注 #pruned-branch 及原因，
移入 枯枝（Archive） 并设置 archived: true——永久保留、隐藏视野，以备将来回溯。
```

### 11. 生态盘点 / 年轮
- **场景**：年度总结或分发前
- **指令**：
```
做一次森林生态盘点：
1. 各领域种子的年轮（开花数、果实数、认知演变）；
2. 全库链接网络健康度（孤立节点、养分最集中区域）；
3. 给出下一年建议生长的方向。
输出到 log.md 或单独报告。
```

## 附：执行铁律
1. **只增不删**：土壤保留原始性；任何删除/移动前先列清单，经确认后执行
2. **一概念一叶**：概念独立成叶，不堆叠在单一笔记里
3. **一素材一枝条（默认单条处理）**：每份文献/素材独立成枝，不合并；除非明确提示"合并"
4. **全部建链**：每个文件必须可被链接（原始文件 ↔ 枝条 ↔ 概念叶 ↔ 树干）
5. **同步更新**：任何结构调整后，同步更新相关文档与 log.md（副本为分发模板时保持纯净）
6. **确认制**：重大操作（改名、移动、删除、归档）先说明影响范围，再执行
