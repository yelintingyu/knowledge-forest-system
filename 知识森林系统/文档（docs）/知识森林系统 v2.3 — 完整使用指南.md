
# 🌳 知识森林系统 v2\.3 — 完整使用指南



> 本指南将带你从零开始，完成系统搭建、播种生根、开花结果、反哺进化的完整闭环。
> 

---



## 一、准备工作



### 1\.1 安装 Obsidian 及必需插件



1. 下载并安装 [Obsidian](https://obsidian.md)。

2. 创建一个新的 Vault（或使用已有 Vault）。

3. 打开 **设置 → 社区插件**，关闭安全模式。

4. 浏览并安装以下插件：

    - **Dataview**（数据查询引擎）

    - **Templater**（模板引擎）

    - **Local REST API**（可选，用于外部 AI 访问）

        

### 1\.2 配置 Templater



1. 打开 **设置 → Templater**。

2. 将 **Template folder location** 设置为 `模板（templates）`（稍后会创建）。

3. 建议开启 **Trigger Templater on new file creation**。

    

### 1\.3 获取本系统的模板与规则



知识森林系统的系统文件（`模板（templates）`、`文档（docs）`、`提示词（prompts）`、`工具（tools）`、`示例（examples）`）位于 Vault 根目录；使用区文件夹位于 `森林知识库/` 子目录（见第二节）。



---



## 二、初始化：创建文件夹结构



以下使用区文件夹已建好，统一位于 **`森林知识库/` 子目录**下（与根目录的系统文件夹分离）：



|文件夹名|用途|
|---|---|
|`土壤（soil）`|存放所有原始碎片（土壤），只增不删|
|`花朵（Flowers）`|AI 生成的开花方案存放处（**v2.7 起位于各领域文件夹内**）|
|`果实（Fruits）`|实践后的果实复盘笔记（**v2.7 起位于各领域文件夹内**）|
|`堆肥（Compost）`|落叶堆肥：单片黄叶/孤立碎片，提取摘要后存放（**全森林共享**，施肥后所有根系吸收）|
|`枯枝（Archive）`|枯枝仓库：被剪枝条永久保留（隐藏视野）|



**领域文件夹（种子）** 每当你开拓一个新领域时才需要创建。例如你决定深耕“读书”，就新建一个 `读书/` 文件夹。

领域内建议建两个子文件夹：**`枝条（branches）`**（放文献笔记，一文献一枝条）和 **`叶片（leaves）`**（放概念叶，一概念一叶）；树干笔记与种子笔记放在领域根目录。

主干和叶子都会在这里生长。



---



## 三、播下第一颗种子



种子就是一个你自主确定的领域名。



### 3\.1 创建种子笔记



1. 按 `Ctrl/Cmd + P`，输入 `Templater: 插入模板`，选择 `t-core-seed`。

2. 将笔记标题改为你的领域名，例如 **“读书”**。

3. 在 `## 领域说明` 中简要描述范围。

4. 笔记会自动带上 `#core-seed` 标签和 `type: core-seed` 元数据。

    

### 3\.2 种子状态说明



|状态|含义|
|---|---|
|`dormant`|休眠期：已创建，暂无碎片关联，无树干|
|`sprouting`|发芽期：已链接到至少一个土壤碎片，或正在生成树干|
|`grown`|成树：已具备完整主干和枝叶，经历过至少一次开花|



新建的种子默认为休眠状态，等待你投喂养分。



---



## 四、蓄土与生根



### 4\.1 蓄土：放入原始碎片



把你日常遇到的任何有价值信息直接丢进 `土壤（soil）`：



- 一篇好文章的链接或全文复制

- 一段读书摘录

- 一个突然冒出的灵感

- 一次会议或谈话的记录

- 一张截图

    

**不要求整理，不要求分类。** 保留原貌，打上 `#soil` 标签更佳。



### 4\.2 生根：让碎片连接到大树



**方式一：手动生根**



1. 打开 `土壤（soil）` 中的某个碎片。

2. 为它打上标签（如 `#阅读方法`、`#笔记术`）。

3. 在笔记中添加双链：`[[读书]]`（链接到你的种子笔记）。

    

**方式二：AI 辅助生根（Work Buddy）**



如果你配置了 Work Buddy，可以命令它：“扫描 土壤（soil） 中的新碎片，分析内容并建议链接到哪些已有领域”。AI 会推荐标签和双链，你确认后自动建立。



**生根后的效果**



- 该碎片不再是孤岛，而是“读书”树的养分来源。

- 同一碎片可以链接到多棵树（比如同时滋养“读书”和“写作”）。

- 碎片的链接数越多，养分浓度越高，未来开花时被优先调取。

    

---



## 五、长干：立树干·长枝条

种子确定（领域）后即可立干；每一份营养文献长成一根枝条，枝条上挂概念叶。

### 5.1 立干：创建树干

1. 按 `Ctrl/Cmd + P`，选择 `Templater: 插入模板`，选择 `t-trunk`（树干模板）。

2. 标题改为 `树干-领域名`（如 `树干-读书`）。

3. 填写**领域基石**（该领域不证自明的前提）。

4. 后续每吸收一份营养，把提炼出的**底层逻辑**追加到 `## 底层逻辑`（编号管理）。

### 5.2 长枝条：文献拆解为概念叶（一文献多叶）

1. 新文献投入 `土壤（soil）` 后，AI 分析其与该领域的相关性。

2. 相关 → 用 `t-branch`（枝条模板）创建文献笔记（`type: branch`），`parent-node` 指向树干，如 `第一性原理-读书笔记`。

3. AI 提取文献的核心概念清单（通常 3~10 个），每个概念创建一片概念叶（`t-leaf`），`parent-node` 指向该枝条。

4. 概念叶标注 `来源营养（文献）` 指向枝条；概念叶之间、与树干之间建立链接。

5. 核心文献还可先用 `t-geometric-trunk` 做几何化解构，作为底层逻辑的阶段性输入。

### 5\.3 更新种子状态



回到你的种子笔记 `读书.md`，将 `status` 改为 `sprouting` 或 `grown`。



---



## 六、展叶：概念知识积累

叶片 = 领域内不断增加的概念知识（一概念一叶），通常挂在枝条上：

1. 按 `Ctrl/Cmd + P`，选择 `Templater: 插入模板`，选择 `t-leaf`（叶片模板）。

2. `parent-node` 必须填写：优先链接到**所属枝条**（如 `[[第一性原理-读书笔记]]`），或树干概念（底层逻辑）。

3. 填写概念定义、我的理解、来源营养（文献/碎片）以及延伸链接。

叶子会自动获得初始营养值 `nutrition: 1`，被其他笔记链接越多，营养值越高。

## 七、开花：问题驱动的方案生成



### 7\.1 提出问题



1. 按 `Ctrl/Cmd + P`，选择 `Templater: 插入模板`，选择 `t-question`。

2. 清晰描述你的问题、背景和已有思考。

3. 将笔记保存在合适位置（建议放在对应领域文件夹或根目录）。

    

### 7\.2 触发开花



向 Work Buddy 发送指令：



> “基于当前问题，在知识森林中开花。”
> 
> 



AI 会执行以下流程：



1. 读取你的问题笔记。

2. 扫描整个 Vault，检索相关土壤碎片、种子、主干概念、枝叶、历史果实。

3. 进行知识碰撞，生成 **2\-5 个候选解法**。

4. 每个解法自动创建为一个 `花-问题标题-编号.md`，存入**所属领域的 `花朵（Flowers）` 文件夹**（v2.7）。

5. 将花笔记的链接回写到问题笔记的 `## 已开之花` 区域。

    

### 7\.3 每朵花包含的信息



- 方案核心理念

- 养分来源（链接到哪些知识碎片）

- 创新程度 / 风险等级 / 所需资源

- 执行步骤草案

- 预设成功标准

- 潜在风险与假设

    

### 7\.4 筛选方案



审查所有花朵，根据创新程度、风险和资源，选择一朵或多朵开始实践。



---



## 八、结果：实践与评定



### 8\.1 小果评定（直接答案类）



适用场景：方案简单、一次性执行、结果即时可见。



1. 实践完成后，按 `Ctrl/Cmd + P`，选择 `Templater: 插入模板`，选择 `t-fruit-review`。

2. `fruit-type` 选择 `small`。

3. 在 `result` 字段手动选择 `good` 或 `bad`。

4. 记录成功或失败的原因。

    

### 8\.2 大果评定（项目/任务类）



适用场景：多步骤执行、有可测量的业务指标。



**步骤一：生成果实判定标准**



在开始执行前，向 Work Buddy 发送指令：



> “为此大果生成果实判定标准。”
> 
> 



AI 会读取花笔记，生成 **4 个判定标准**，每个包含：



- 指标名称（如“阅读完成率”）

- 衡量方法（如“实际读完页数 / 计划页数”）

- 优/好/差/坏四级阈值建议

    

你确认或调整这些标准后，开始执行。



**步骤二：执行后评级**



1. 执行结束后，用 `t-fruit-review` 创建果实复盘笔记。

2. `fruit-type` 选择 `big`。

3. 将实际数据填入 `## 大果专属：4 个判定标准` 区域。

4. Work Buddy 会对照标准给出初始评级建议，由你最终确定。

    

### 8\.3 大果评级决策树



```Plain Text
是否达到预设成功标准？
├── 否，且无任何正面效果 → ❌ 坏果
├── 否，但有部分价值或教训 → ⚠️ 差果
└── 是 → 是否产生超额正面效果？
    ├── 是 → 🌟 优果
    └── 否 → ✅ 好果
```



### 8\.4 长周期复评（仅大果）



评定 **30 天后**，回到果实笔记，在 `## 长周期复评` 中记录长期效应：



- 优果后来暴露隐患 → 降级为好果或差果

- 差果经后续改良有效 → 升级为好果

    

---



## 九、反哺：让经验回归土壤



每次果实评级完成后，在复盘笔记中记录反哺建议：



|果实等级|反哺动作|
|---|---|
|🌟 优果|提取可复用模式，写入主干概念作为“黄金标准”，所用枝叶营养 \+3|
|✅ 好果|记录为成功案例，链接到所用枝叶，营养 \+1|
|⚠️ 差果|生成改良建议叶子，营养 \+0\.5，添加警示标签|
|❌ 坏果|生成避坑警示叶子，营养不增但警示权重增加，未来开花时自动规避|



同时检查：**这个果实是否影响了领域种子的认知？** 如果是，回到种子笔记更新年轮日志。

## 十、嫁接：跨界创新



### 10\.1 主动嫁接



1. 按 `Ctrl/Cmd + P`，选择 `Templater: 插入模板`，选择 `t-graft`。

2. `scion`（接穗）：来自 A 领域的某个概念或叶子。

3. `rootstock`（砧木）：B 领域的一个枝条。

4. 阐述嫁接设想和理论基础。

5. 触发开花，生成杂交方案。

    

### 10\.2 AI 建议嫁接



Work Buddy 可以定期扫描不同领域树的结构相似性，推荐可能的嫁接对。AI 必须输出三项可行性评估：



- **问题结构同构性**：底层问题模式是否相似？

- **机制可迁移性**：成功机制能否抽象为通用原则？

- **逻辑自洽性**：迁移后在新领域是否无矛盾？

    

缺少任一项论证的嫁接建议仅作为灵感提示。

## 十一、森林维护



### 11\.1 修剪黄叶（建议每月一次）



1. 查看 Obsidian 仪表盘（Dataview 查询结果）。

2. 找到连续 90 天未被引用、链接数 ≤1 的“黄叶”。

3. 选择操作：

    - **激活**：重新阅读并链接，黄叶变绿。

    - **落叶**：打上 `#fallen-leaf` 标签，移至 `堆肥（Compost）` 文件夹。提取摘要保存，删除大量冗余内容。

        

### 11\.2 清理贫瘠土壤（建议每半年一次）



1. 让 Work Buddy 分析链接数为 0 且超过 180 天的碎片。

2. AI 给出“低潜力”判断后，你手动确认清除。

3. 移至 `堆肥（Compost）`：提取摘要后存放，可删除原文件；堆肥可纳入土壤，开花时适时激活（施肥）。

    

### 11\.3 年轮日志（每年一次）



每年年底，在每颗种子笔记的 `## 年轮日志` 中记录：



- 当年开花次数

- 各类果实数量

- 领域认知的演变或修正
