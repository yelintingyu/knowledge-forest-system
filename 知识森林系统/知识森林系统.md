```Markdown
# 🌳 知识森林系统 (Knowledge Forest) v2.3

> 以**原始碎片为土壤**，以**自主确定的领域为种子**（如“读书”“新媒体”“AI”），用**根系网络吸取养分**，长出**几何主干**，通过**多花绽放、大小果分级**实现知识自生长的生命系统。

## 核心理念
- **土壤**：所有未加工的信息（摘录、灵感、日记等）是肥沃的土壤，只增不删，保留原始性。
- **种子**：一个**你自主确定的领域名称**（如“读书”“新媒体”“AI”），决定了一棵树所代表的知识领域。
- **根系**：双链与标签构成的连接网络，从土壤中有选择地吸收特定养分。同一碎片可滋养多棵树。
- **树干**：AI 解构一篇经典文献后形成的几何知识图谱。
- **枝叶**：日常积累的案例、工具、心得，附着在树干概念上。
- **开花**：面对真实问题，AI 调取根系吸收的养分，碰撞出多个候选解法。可要求生成“沙盒测试”。
- **果实**：实践后评出**大果（项目/任务，AI 动态生成 4 个判定标准）** 和**小果（直接答案，人为判定好/坏）**。
- **反哺**：果实分解回土壤，成为新一轮生长的养分。

## 隐喻对应表

| 自然隐喻 | 系统功能 | Obsidian 实现 |
|---------|----------|----------------|
| 土壤 | 原始碎片信息 | `土壤（soil）` 或 Daily Notes，带 `#soil` 标签 |
| 种子 | 领域标签（如“读书”） | `#core-seed` 笔记，可休眠 |
| 根系 | 链接网络 | 双链、Dataview 统计吸收量 |
| 树干 | 几何知识主干 | MOC笔记 + Mermaid 图 |
| 枝叶 | 扩展知识 | 链接到树干概念的子笔记 |
| 开花 | 生成多个解法 | `花-` 笔记，由 Work Buddy 创建 |
| 嫁接 | 跨界创新 | `嫁接-` 笔记，需通过可行性评估 |
| 大果 | 项目/任务结果 | AI 生成 4 个判定标准，四级评定 |
| 小果 | 直接答案结果 | 人为判定好/坏 |
| 反哺 | 果实化为新养分 | 写回土壤碎片或种子日志 |

## 快速开始
1. 安装 [Obsidian](https://obsidian.md)，启用插件：**Dataview**、**Templater**、**Local REST API**（可选）。
2. 将本仓库作为你的 Obsidian Vault 或复制文件到现有 Vault。
3. 阅读 `文档（docs）/搭建指南（setup-guide）.md` 完成配置。
4. 播下第一颗种子：用 `种子模板（t-core-seed）` 创建一个你关注的领域（例如“读书”）。
5. 种树：用 `几何主干模板（t-geometric-trunk）` 构建树干，搭配 Work Buddy 生成几何主干。
6. 开花：用 `问题模板（t-question）` 写下问题，触发 Work Buddy 生成多朵花。
```

```Markdown
# 思想：土壤、种子与森林

## 1. 土壤是一切养分的来源
所有未经整理的原始信息——你的划线、灵感、会议记录、随手截图——都是**土壤**。它们混杂、低结构、不加评判，是知识生长的物质基础。土壤只增不删，保留原始性。

## 2. 种子是你选定的知识领域
你自主确定的一个**领域名称**（如“读书”“新媒体”“AI”）就是一颗**种子**。**种子即大树的名字**，是根系、树干、叶片、开花、结果的集合，而非一篇具体文献。它代表一棵知识树将深耕的方向。种子决定了“这棵树要长成什么领域”，并指导根系往该方向吸收养分。

## 3. 根系是活的选择网络
孤立碎片没有力量。**根系**通过双链、标签和 AI 自动关联，将土壤中的碎片与种子、树干连接起来，就像吸收氮、磷、钾一样，让特定养分流向特定的树。同一碎片可以滋养多棵树，形成地下菌根网络。

## 4. 从树干到开花结果
- **树干**：AI 对一篇营养文献进行几何化解构，形成领域骨架。
- **开花**：遇到问题，AI 从根系调取关联养分，碰撞出多个解法。
- **结果**：大果（项目/任务）由 AI 动态生成 4 个判定标准，小果（直接答案）人为判定。好果和坏果都分解回土壤，成为新养分。

## 5. 园丁与光合作用
你是园丁，负责播种、嫁接、修剪、评判果实。AI 是光合作用系统，负责自动提炼、生成、追踪。
```

```Markdown
# 系统架构：问题驱动的森林生态

## 整体流程
1. **蓄土**：所有碎片信息直接丢入 土壤（soil），无需整理。
2. **播种**：用 `种子模板（t-core-seed）` 定义你关注的领域（如“新媒体”），允许同时多颗、允许休眠。
3. **生根**：手动或 AI 辅助将 土壤（soil） 碎片链接到种子和主干。新文件加入时 AI 自动扫描已有大树，匹配建链。
4. **长干**：投入营养文献，AI 分析相关性建链，提炼底层逻辑形成树干；核心文献可用几何主干解构后并入。
5. **展叶**：日常笔记链回主干概念。
6. **开花**：提问 → AI 检索全林养分（包括未链接碎片）→ 生成 2-5 个解法（含创新度、风险、资源标签）。
7. **结果**：大果实践后 AI 生成 4 个判定标准并建议评级，小果人为判好/坏。
8. **反哺**：果实分解为土壤新养分，修正领域认知或生成避坑警示。
9. **修剪**：处理黄叶、剪枝；极长期无链接的碎片经人工确认后移除。

## 技术实现
- **Obsidian** 知识库本体，双链和 Frontmatter 驱动。
- **Dataview** 动态查询营养值、黄叶、可开花枝条。
- **Work Buddy** 外部 AI 应用，通过文件读写或 Local REST API 交互，所有操作记录日志。
```

```Markdown
# 土壤与种子规则

## 土壤（原始碎片信息）
- 所有未加工的信息（摘录、灵感、聊天记录、随手记）均视为**土壤**。
- 存放位置：`土壤（soil）` 文件夹或 Daily Notes。
- 不要求立即分类，保留原貌。
- 可选择性打上标签 `#soil` 以备检索。
- **土壤只增不删，保留原始性**。仅在极长期无链接且经人工确认后才移除。

## 种子（核心领域）
- 种子是**你自主确定的知识领域名称**，如“读书”“新媒体”“AI”“产品设计”“投资”等。它就是这棵树的身份标签。
- 种子笔记用 `#core-seed` 标签，`type: core-seed`，笔记标题即为领域名（如“读书”）。
- 可以**随时种、同时种多颗种子**。
- 创建种子时，允许对应文件夹为空（休眠期）。当土壤中出现与该领域相关的碎片、或你主动投入营养文献后，种子“发芽”，长出树干。

## 种子的生命周期
- **休眠期**：创建后无关联碎片、无树干，等待条件成熟。
- **发芽**：首次链接到土壤碎片或生成几何主干。
- **成树**：具备完整主干和枝叶，经历过至少一次开花。
- **分株**：当某根枝条的养分总量超过主干的 40%，且已独立开花，可考虑分离为新树（新领域种子）。
- **年轮日志**：每年年底，在种子笔记中更新一段“年轮”，记录当年关键生长（开花数、果实数、领域认知的演变）。

## 不建议合并
原则上不合并领域种子，保持细粒度有助于精确追踪不同知识领域。如需关联，可通过嫁接或双链连接。
```

```Markdown
# 根系规则：从土壤吸收养分

## 根的本质
根是**连接网络**。它把土壤中的碎片（原始信息）与种子、树干节点关联起来，实现“选择性吸收”。  
每个原始碎片就像腐烂的叶子、果实或昆虫，**身上携带多种元素（标签）**，可以被多棵树的根系吸收。同一碎片可以同时滋养多棵树。

## 生根方式

### 方式一：手动生根（初次引入 + 全局扫描）
- **首次手动/AI生根**：当你放入一个新文件到土壤（soil），你或 Work Buddy 分析其内容，给它打上**标签**（标签即元素，如 `#用户体验`、`#转化率`、`#认知偏差`）。同时，手动或通过 AI 建议，将该文件链接到相关种子和/或主干概念。这一步建立初始根系。
- **自动建链（已存在多棵树时）**：当放入第二个文件，AI 不仅会为第二个文件与当前的树建链，还会**自动扫描已有大树**，检查第二个文件是否包含已有树需要的养分（即是否有相同的标签或语义匹配）。若有，自动建立双链。这样根系会随着新文件的加入而自动延伸。
- **长出新生枝叶的提示**：当新文件携带了某个已有树尚未覆盖的标签/概念，系统会提示“该碎片含有树『XX』的新养分，是否在主干上长出新枝叶？”

### 方式二：按需生根（开花时动态检索）
- 当你提出一个问题触发开花时，Work Buddy 会在全 Vault 中**临时检索**与问题相关的碎片，即使这些碎片之前未被任何树链接。
- 检索到的碎片若对生成方案有价值，会被临时用作养分；同时，开花结束后，AI 会建议你是否将这些碎片**永久链接**到相关树上（“将这次开花发现的养分固定为根系”）。

## 根的健康：链接数即吸收强度
- 一个土壤碎片被链接的次数越多，说明它被多棵树吸收，养分浓度越高。
- 在碎片笔记的 Frontmatter 中可用 `links-count` 字段记录（由 Dataview 自动统计），或直接通过双链数量判断。

## 根系修剪：仅针对长期无链接的碎片
- **原始文件原则上是只读、只增、不删**，以保持土壤的原始性。
- 但当土壤碎片积累极多（例如 > 500 条），且某些碎片**连续 180 天** `links-count: 0`，可启动清理评估：
  - AI 分析该碎片对既有树和未来可能开花的潜在影响。
  - 若判断为“低潜力”，则提示你**手动清除**（移至 `堆肥（Compost）`（提取摘要后存放，可删除原文件））。
- 极少链接但未达阈值的碎片，由 AI 定期分析其对开花结果的影响，给出“保留/清除”建议，你审核后操作。

## 根网可视化
- 利用 Dataview 查询每个碎片的 `file.inlinks` 和 `file.outlinks`，可绘制出“菌根网络”——哪些碎片同时滋养了多棵树。
```

```Markdown
# 养分浓度规则

## 浓度定义
- 土壤碎片的养分浓度由**被链接次数**体现。
- 链接数 ≥ 5：高浓度（核心养分）
- 链接数 2-4：中浓度
- 链接数 1：低浓度
- 链接数 0：未激活

## 浓度对开花的影响
- 开花检索时，高浓度碎片优先调取。
- 低浓度碎片在开花时若被用到，可提示“是否将其固定为永久根系”，提升其链接机会。

## 浓度与清理
- 链接数为0的碎片，若超过 180 天仍未链接，可手动清除（见根系修剪规则）。
- 链接数 1 的碎片，每年由 AI 分析一次对开花结果的潜在影响，若无价值则建议清除。
- 原始碎片不因链接多而被“消耗”，链接越多越好，土壤只增不删（除上述清理）。
```

```Markdown
# 开花规则：问题驱动的多方案生成

## 触发方式
**仅由问题触发。**
1. 用 `问题模板（t-question）` 创建问题笔记。
2. 通过外部 Work Buddy 发送指令：“基于当前问题，在知识森林中开花”。

## Work Buddy 多花生成流程
1. **问题理解**：读取问题笔记全文。
2. **根系检索**：扫描 Obsidian Vault，找到与问题相关的：
   - 土壤碎片（包括未链接的，按需检索）
   - 领域种子
   - 几何主干概念及枝叶
   - 历史果实（尤其是避坑警示和可复用模式）
3. **开花前检索报告（默认关闭，可激活）**  
   - 若激活，Work Buddy 先输出“找到的养分清单”，由你确认或补充后再生成方案。  
   - 当前版本默认跳过，直接进入方案生成。
4. **知识碰撞与方案生成**：
   - AI 将检索到的知识片段进行组合、类比、嫁接，生成**多个候选解法**。
   - 方案数量由 AI 根据问题复杂度和养分多样性动态决定，通常 2-5 个。若仅有一个靠谱方案，允许生成1个；若养分丰富，最多不超过7个。
   - 每个方案除核心理念外，必须标注：
     - **创新程度**（低/中/高）
     - **风险等级**（低/中/高）
     - **所需资源**（时间、精力、外部依赖）
5. **写入花笔记**：为每个方案创建 `花-问题标题-编号` 笔记，包含上述信息和执行步骤草案、成功标准、风险假设。

## 人工筛选与测试
- 审查所有花朵，根据创新程度、风险、资源选择一朵或多朵实践。
- 可要求 Work Buddy 生成“沙盒测试”方案，低成本验证关键假设。
- 实践过程记录在花笔记的 `## 实践日志`。

## 与嫁接的关系
- 若方案中需要跨领域知识，Work Buddy 会自动创建嫁接笔记，并将嫁接枝作为养分来源。
- 你也可以在问题笔记中主动要求嫁接，如“用游戏化的即时反馈解决员工培训参与度”。
```

```Markdown
## 主动嫁接
- 使用 `嫁接模板（t-graft）` 模板，指定接穗（来自A枝的叶子或概念）和砧木（B枝）。

1. **问题结构同构性**：两个领域是否存在相同或相似的底层问题模式？

3. **逻辑自洽性**：迁移后的方案在目标领域的语境下是否无矛盾、可行？

## 嫁接成功标准
- 优/好果：嫁接处建立永久链接，可能催生新分支。
- 差/坏果：记录失败归因，打上 `#failed-graft`，用作警示。
```

### 文档（docs）/规则（rules）/结果与反哺（fruiting-and-feedback）.md

```Markdown
# 结果与反馈规则：大果与小果

## 果实分类
- **大果**：对应**项目或任务**，需要多步骤执行，结果有明确可测量的业务指标。
- **小果**：对应**可直接回复的答案或一次性操作**，执行简单，结果即时可见。

## 小果评定（人工判定）
- **好果**：答案正确、有用，解决了问题。
- **坏果**：答案错误、无用，或产生误导。
- 由你在 `果实复盘模板（t-fruit-review）` 中手动选择，无需 AI 参与。

## 大果评定（AI 辅助生成标准 + 人工确认）
1. 当你在花笔记中启动大果实践，Work Buddy 读取花笔记的全部内容（问题、方案、养分来源、成功标准）。
2. Work Buddy 生成 **4 个响应判定标准**，每个标准包含：
   - 指标名称（如“用户留存率变化”）
   - 衡量方法（如“A/B 测试后实验组与对照组的差值”）
   - 优/好/差/坏四级阈值建议（如：≥+10% 为优，+5%~10% 为好，0~+5% 为差，负值为坏）
3. 你确认或调整这些标准后，开始执行。
4. 执行结束后，AI 根据实际数据对照标准，给出初始评级建议，由你最终确定。

## 大果评定决策树
1. **是否达到预设成功标准？**
   - 未达到，且无任何正面效果或产生负面效果 → **❌ 坏果**
   - 未完全达到，但有部分价值或学到了重要教训 → **⚠️ 差果**
   - 达到 → 进入问题2
2. **是否产生了超出预期的额外正面效果？**
   - 是 → **🌟 优果**
   - 否 → **✅ 好果**

## 长周期复评（仅大果）
- 评定 30 天后复评长期效应，记录于 `## 长周期复评`。
- 若优果后来暴露隐患，降级为好果或差果，并补充警示。
- 若差果经后续改良变成有效方案，可升级为好果。

## 分级反哺
- **优果**：提取可复用模式写入主干，枝叶营养 +3。
- **好果**：记录为成功案例，枝叶营养 +1。
- **差果**：生成改良建议叶，营养 +0.5，添加警示。
- **坏果**：生成避坑警示叶，营养不增但警示权重增加。

所有果实都必须检查是否影响领域种子的认知，若需修订则更新种子年轮日志。
```

### 工具（tools）/伙伴示例（obsidian-buddy-example）.py

```Python
import requests
import json
import openai
import datetime

OBSIDIAN_API = "http://localhost:27123"
VAULT_NAME = "knowledge-forest"
LOG_PATH = "系统（System）/operation-log.md"

def log(message):
    with open(LOG_PATH, "a") as f:
        f.write(f"{datetime.datetime.now().isoformat()} - {message}\n")

def search_notes(query):
    resp = requests.post(f"{OBSIDIAN_API}/search/", json={"query": query})
    return resp.json()

def read_note(path):
    resp = requests.get(f"{OBSIDIAN_API}/vault/{VAULT_NAME}/{path}")
    return resp.text

def create_note(path, content):
    resp = requests.post(f"{OBSIDIAN_API}/vault/{VAULT_NAME}/{path}", data=content.encode('utf-8'))
    return resp.status_code == 200

def bloom(question_path):
    log(f"开始开花：{question_path}")
    question_content = read_note(question_path)
    relevant = search_notes(" ".join(question_content.split()[:30]))
    with open("提示词（prompts）/生成花朵（generate-flowers）.md", "r") as f:
        prompt_template = f.read()
    prompt = prompt_template.replace("{{question}}", question_content).replace("{{knowledge_chunks}}", json.dumps(relevant))
    response = openai.ChatCompletion.create(
        model="gpt-4",
        messages=[{"role":"user", "content": prompt}]
    )
    flowers_text = response.choices[0].message.content
    flower_list = flowers_text.split("## 方案")
    for i, flower in enumerate(flower_list):
        if i == 0:
            continue
        flower_content = f"## 方案{flower.strip()}"
        create_note(f"花朵（Flowers）花-{question_path}-{i}.md", flower_content)
    log(f"完成开花：创建了{len(flower_list)-1}朵花")

if __name__ == "__main__":
    bloom("Questions/如何提升用户留存.md")
```
